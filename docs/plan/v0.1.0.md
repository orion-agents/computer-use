# v0.1.0 计划：macOS Computer Use MVP

> 状态：计划，尚未实现。验收标准是交付目标，不是已经取得的测试结果。

## 版本目标

在一台 macOS 电脑上，通过一个本地命令运行**单个确定性的桌面任务**：使用 TextEdit 打开项目提供的示例文本，复制指定内容到新文档并保存到独立工作目录；程序独立读取结果文件，判断其内容是否符合预期，输出机器可读的执行报告。

此版本验证最核心的链路：**驱动真实桌面 → 完成任务 → 检查结果 → 如实报告**。它不依赖大模型决策，也不承诺通用自然语言操作。

## 目标场景

使用项目自带的非敏感 UTF-8 示例文件，例如 `fixtures/input.txt`，其中包含固定的一行 `Computer Use MVP`。运行者提供一个专门的空工作目录。执行器在 TextEdit 中打开示例，复制该行到新文档，将其保存为工作目录下的 `result.txt`。验证器从磁盘读取目标文件，并对内容进行精确比较（允许文件末尾一个换行，具体规则需在实现与测试中固定）。

结果报告中，只有实际文件检查通过时才能标记 `success`；点击成功或 TextEdit 显示内容不构成成功。失败、超时、取消与权限不足应分别可辨认。

## 范围

### 必须具备

1. **单一任务入口**：提供本地 CLI，接收工作目录、超时时间等必要参数，执行固定的 MVP 任务。CLI 的最终命令和参数在实现时确定并写入 README。
2. **真实桌面动作**：通过可替换的桌面驱动完成 TextEdit 的打开、选择、复制、粘贴与保存。优先调查可复用的开源驱动，核实许可证、平台权限和稳定性；备选为实现最小 macOS 适配层。
3. **状态与结果**：记录任务 ID、状态、开始和结束时间、步骤状态、错误类别与产物路径；以 JSON 文件输出。CLI 退出码应区分成功与非成功，并在实现文档中明确。
4. **独立结果验证**：限制产物位于用户指定工作目录，读取文件并检查内容；缺失、内容不匹配和读取失败不能返回成功。
5. **权限与中断**：启动前检查必要的 macOS 辅助功能权限；仅当所选驱动确实需要屏幕录制权限时才要求它。权限不足、应用不可用、超时或用户中断时停止并给出明确结果与指引。
6. **重跑与清理**：在隔离的临时或指定空目录中运行，重复运行不误用上一次结果；提供说明如何清理项目生成的文件。不删除用户已有文件。
7. **基本测试与文档**：覆盖结果校验和关键失败分支；记录系统前置条件、安装、运行、权限和结果格式。

### 明确不在 v0.1.0 内

- 自然语言任务规划、模型调用、模型训练或自动选择模型。
- 多 Worker 并发、Manager 调度、远程控制、云服务或桌面虚拟化。
- Windows / Linux 支持、通用任意应用适配、自动处理未知弹窗。
- MCP 服务器、完整 UI 产品、自动录屏与截图归档。
- 登录第三方账号、发送消息、购买、发布内容或操作真实业务数据。
- 声称操作系统级沙箱、完整安全隔离或可靠的跨应用泛化能力。

## 设计草图

```text
CLI / 固定任务
    ↓
任务执行器 ──→ 桌面驱动（接口；具体实现待验证）
    ↓                  ↓
状态与步骤记录        TextEdit
    ↓
独立文件验证器 → JSON 报告 + 退出码
```

- **执行器**：顺序执行步骤，跟踪超时、取消和错误，不把底层工具返回值直接当成任务成功。
- **驱动**：封装界面观察和动作；接口与具体实现根据最小真实任务确定，不提前设计完整跨平台抽象。
- **验证器**：从任务产物读取实际结果，而不是读取模拟状态。
- **报告**：默认只记录步骤名称、状态、耗时、错误类别和产物路径；不保存正文、截图、剪贴板内容或密钥。涉及剪贴板时需在运行说明中告知用户，执行后不能假设系统剪贴板仍保持原样。

桌面工具使用 macOS 系统授权执行动作；目标路径检查与允许动作列表只定义应用层范围，**不等同于强制沙箱**。在敏感内容可能可见的环境中使用前，使用者需了解所选驱动及其数据处理方式。

## 实施顺序

1. **验证可行性**：比较至少一个现有 macOS 驱动与最小原生实现，确认许可证、安装、权限、目标应用操作与取消行为；记录选择理由和限制。
2. **建立任务夹具**：准备示例文件、独立工作目录和精确的结果验证规则。
3. **实现执行闭环**：完成最小 CLI、驱动接入、任务步骤、状态和结果报告。
4. **覆盖失败路径**：验证缺权限、目标应用不可用、结果不正确、超时及重复运行。
5. **真实桌面验收**：在 macOS 上按下方标准运行并保存脱敏证据，再完善文档。

## 验收标准

- [ ] 在文档说明的 macOS 环境中，从干净工作目录运行真实桌面任务，**连续 3 次**得到内容正确的 `result.txt`，报告为 `success`，进程返回成功退出码。
- [ ] 检查结果内容与报告一致：篡改或移除结果文件时，验证器给出非成功状态；不能仅凭动作返回值报告成功。
- [ ] 缺少必要系统权限时，程序停止并提供可操作的权限指引；不报告成功。
- [ ] 应用不可用、超时及用户取消分别能得到清晰状态或错误类别，且不误报成功。
- [ ] 重跑时不会误把前次产物当作本次结果，不覆盖或删除工作目录之外的用户文件。
- [ ] 报告包含任务 ID、环境版本、步骤状态、耗时、验证结论和产物路径；默认不包含截图或文本正文。
- [ ] 自动测试覆盖验证器和关键错误处理；真实桌面运行证据单独列出，模拟测试不能替代 live proof。
- [ ] README 写明安装与运行方式、权限、数据处理、已知限制和实际验证环境。

连续 3 次只是该单一任务的 MVP 验收门槛，不代表真实业务场景的整体成功率。截图、日志或其他证明材料若包含敏感信息，不应提交到公共仓库。

## 暂定风险与待决事项

- macOS 版本、TextEdit 的界面和系统弹窗可能影响流程；先明确实际支持的版本。
- 系统辅助功能与屏幕录制授权取决于实现，不能承诺绕过权限提示。
- 选择的第三方驱动是否可用、许可证是否兼容，需要实际评估；不能把依赖的功能描述当作实测结论。
- 本机桌面动作可能改变焦点或剪贴板；执行期间需要用户知情，后台无干扰操作不在首版承诺范围内。
- 模型成本、Worker 并发和跨平台方案在本版本不作性能承诺。
