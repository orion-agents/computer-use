# 项目整体目标

> 状态：规划中。本文描述项目希望达到的方向，不代表这些能力已经实现。

## 愿景

让 AI Worker 能够在明确的任务边界内操作电脑，完成跨应用工作，并向人或 Manager 提供可核验的结果、执行状态和必要证据。

这个项目关注桌面操作的完整闭环：**接收任务 → 观察界面 → 执行动作 → 验证结果 → 报告状态**。操作调用成功并不等于任务成功；最终结果需要通过适合任务的检查来确认。

## 要解决的问题

- **完成状态不明确**：点击成功不代表文件已保存，也不代表任务目标达成。
- **失败难定位**：界面变化、弹窗、焦点和权限问题可能让任务中断，使用者需要知道失败位置和原因。
- **协作不透明**：多个 Worker 同时操作桌面时，窗口、焦点和输入设备可能互相干扰。
- **缺乏可比较的数据**：需要记录任务完成率、耗时、操作次数，以及使用模型时可获得的调用量和成本。
- **授权和隐私边界不清楚**：系统需要明确运行范围、所需系统权限，以及哪些数据会被保留或交给外部服务。

这些问题并非本项目独有。项目将参考和评估已有工具，通过真实场景比较来验证自己的价值。

## 目标用户和场景

1. **独立开发者**：在自己的电脑上尝试可靠的本地桌面自动化。
2. **Agent 开发者**：为 Worker 接入可替换的桌面操作能力及结果验证。
3. **Manager/Worker 使用者**：查看任务状态、产物和失败原因，必要时暂停或接管。

潜在场景包括本地文件整理、文档处理、应用间资料转录和软件测试。涉及账号、数据发送或不可逆操作的场景，需要明确的用户授权及对应保护，不属于首个 MVP 的验证任务。

## 核心原则

1. **结果可验证**：针对任务定义成功条件，检查文件、应用状态或其他可观察结果；不把模型的自述当成成功证据。
2. **失败要可见**：区分成功、失败、超时和取消，保留足以定位问题的非敏感信息。
3. **边界清楚**：明确目标应用、工作目录和允许的动作；本地进程仍拥有用户授予的系统权限，这些约定本身不是操作系统沙箱。
4. **可观察、可接管**：长期目标是让用户看到任务状态并能停止或接管；不同系统的能力需要实际验证。
5. **本地优先、最小记录**：默认记录完成验证所需的元数据，不默认保存截图或界面文字；若接入云模型，数据是否离开设备取决于明确配置和用户授权。
6. **可替换、可比较**：优先评估现有桌面驱动，通过清晰接口支持未来替换；不把尚未验证的外部项目能力视为保证。
7. **证据诚实**：区分模拟测试、真实桌面运行和实际业务使用；性能、成功率和成本必须注明环境、样本和测量方法。

## 长期方向

- **可靠执行**：可恢复的任务状态、步骤验证和失败诊断。
- **Manager/Worker 协作**：任务分配、资源占用协调、事件与结果回传。
- **多应用与跨平台**：从 macOS 实际场景出发，逐步评估 Windows 和 Linux。
- **多种接入方式**：在需求和设计明确后考虑 CLI、SDK 或 MCP 等接口。
- **评测体系**：使用可复现任务，对比任务成功率、延迟、资源和成本。
- **隐私与授权**：根据实际威胁模型改进隔离、记录和人机交互。

上述是方向，不是已承诺的版本交付；项目会根据实际用户和实验结果调整。
